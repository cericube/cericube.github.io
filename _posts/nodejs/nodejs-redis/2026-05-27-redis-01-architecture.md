## 1. Redis 개요와 인메모리 데이터 저장 방식 {#session-01}

Redis는 데이터를 빠르게 저장하고 조회하기 위해 사용하는 인메모리 기반 데이터 저장소입니다.  
일반적인 데이터베이스가 데이터를 디스크에 영구 저장하는 것과 달리, Redis는 자주 사용하는 데이터를 RAM에서 바로 읽고 처리하여 빠른 응답을 제공합니다.  

아래 그림을 통해 일반적인 데이터베이스와 Redis의 처리 방식 차이를 확인할 수 있습니다.  

![일반 데이터베이스와 Redis의 처리 방식 비교](/assets/images/nodejs/nodejs-redis/redis-in-memory-comparison.svg)

> 그림의 수치는 구조를 이해하기 위한 예시이며, 실제 속도는 저장 장치와 네트워크, 데이터 크기와 서버 부하에 따라 달라집니다.  

Redis는 다양한 자료 구조와 데이터 만료, 영속성, 복제와 클러스터링 기능을 제공합니다.  
캐시뿐만 아니라 세션, 실시간 랭킹과 메시지 처리에도 활용할 수 있지만, RAM의 용량과 비용을 고려해 필요한 데이터만 저장하는 것이 좋습니다.  

### 🟦 라이선스와 Valkey

Redis는 버전에 따라 라이선스가 다르므로 도입 전에 확인해야 합니다.  

| 버전 | 라이선스 |
| --- | --- |
| Redis 7.2 이하 | BSD-3-Clause |
| Redis 7.4~7.8 | RSALv2 또는 SSPLv1 |
| Redis 8 이상 | RSALv2, SSPLv1 또는 AGPLv3 |

Redis 8 이상을 운영 환경에 도입하거나 관리형 서비스로 제공할 때는 [공식 라이선스 안내](https://redis.io/legal/licenses/){: target="_blank" rel="noopener noreferrer" }를 확인해야 합니다.  

[Valkey](https://valkey.io/topics/introduction/){: target="_blank" rel="noopener noreferrer" }는 Redis의 라이선스 변경 이후 Redis 7.2.4를 기반으로 출발한 BSD-3-Clause 오픈 소스 프로젝트입니다.  
Linux Foundation이 지원하며 Redis 7.2 이하의 주요 명령과 호환되지만, 두 프로젝트가 독립적으로 개발되고 있으므로 이전할 때는 호환성을 확인해야 합니다.  

## 2. Redis의 주요 자료 구조와 활용 사례 {#session-02}

Redis는 단순히 Key와 Value만 저장하는 도구가 아닙니다.  
여러 가지 자료 구조를 제공하므로 상황에 맞게 데이터를 효율적으로 저장하고 처리할 수 있습니다.  

### 🟦 String

가장 기본적인 자료 구조는 String입니다.  
String은 하나의 Key에 하나의 Value를 저장하는 방식입니다.  
예를 들어 로그인 토큰, 인증 코드, 설정값과 조회 수 같은 데이터를 저장할 때 사용할 수 있습니다.  

### 🟦 List

List는 순서가 있는 데이터를 저장할 때 사용합니다.  
데이터를 앞이나 뒤에 추가하고 꺼낼 수 있으므로 대기열을 만들 때 적합합니다.  
예를 들어 작업 처리 목록, 알림 목록과 최근 본 상품 목록 등을 관리할 수 있습니다.  

### 🟦 Set

Set은 중복되지 않는 데이터를 저장할 때 사용합니다.  
예를 들어 이벤트에 참여한 사용자 목록이나 특정 게시글에 좋아요를 누른 사용자 목록을 저장할 수 있습니다.  
같은 사용자가 여러 번 추가되더라도 한 번만 저장되므로 중복 관리에 유리합니다.  

### 🟦 Hash

Hash는 하나의 Key 안에 여러 개의 정보를 묶어서 저장할 수 있는 구조입니다.  
사용자 정보나 상품 정보처럼 여러 속성을 가진 데이터를 저장할 때 편리합니다.  
예를 들어 사용자 이름, 이메일과 나이 등을 하나의 사용자 Key 안에 저장할 수 있습니다.  

### 🟦 Sorted Set

Sorted Set은 Score를 기준으로 데이터를 정렬하여 저장하는 자료 구조입니다.  
게임 점수, 인기 게시글 순위와 검색어 순위처럼 순위가 필요한 기능에 적합합니다.  
데이터를 저장하면서 Score 순서를 유지하므로 실시간 랭킹 기능을 구현할 때 많이 사용합니다.  

어떤 자료 구조를 사용할지 고민될 때는 데이터에 어떤 연산을 자주 수행하는지를 기준으로 판단하면 됩니다.  
입력 순서와 양쪽 끝의 추가·삭제가 중요하면 List, 중복 제거가 필요하면 Set, Score 기준 정렬이 필요하면 Sorted Set을 선택할 수 있습니다.  

## 3. 고성능 처리를 위한 Redis 아키텍처 특징 {#session-03}

Redis가 빠른 이유는 데이터를 메모리에 저장하기 때문만은 아닙니다.  
Redis는 요청을 효율적으로 처리할 수 있도록 설계된 구조를 가지고 있습니다.  

![Redis의 이벤트 루프와 고성능 처리 구조](/assets/images/nodejs/nodejs-redis/redis-architecture.png)

### 🟦 싱글 스레드 기반 명령 처리

Redis는 주요 명령을 대부분 싱글 스레드 방식으로 처리합니다.  
현대적인 Redis는 네트워크 I/O와 백그라운드 작업 등에 추가 스레드를 사용하지만, 명령 실행은 대부분 하나의 스레드에서 처리합니다.  
처음에는 하나의 스레드만 사용한다는 점이 느리게 느껴질 수 있지만, Redis는 메모리에서 매우 빠르게 연산을 수행하고 불필요한 동기화 비용을 줄입니다.  
여러 스레드가 동시에 데이터를 변경할 때 발생할 수 있는 충돌이나 Lock 처리 부담이 적으므로 안정적인 성능을 제공할 수 있습니다.  

### 🟦 이벤트 기반 처리

Redis는 이벤트 기반 처리 방식을 사용합니다.  
여러 클라이언트의 요청을 이벤트 루프에서 빠르게 받아 처리하며 네트워크 요청에 의한 대기 시간을 줄이는 데 유리합니다.  
이러한 구조 덕분에 Redis는 많은 요청을 빠르게 처리할 수 있습니다.  

### 🟦 파이프라이닝

Redis에는 파이프라이닝 기능도 있습니다.  
일반적으로 클라이언트는 명령을 하나 보내고 응답을 받은 뒤 다음 명령을 보냅니다.  
하지만 파이프라이닝을 사용하면 앞선 응답을 기다리지 않고 여러 명령을 연속으로 보낸 뒤 응답을 받을 수 있습니다.  
이를 통해 네트워크 왕복 횟수를 줄이고 전체 처리 속도를 높일 수 있습니다.  

### 🟦 Pub/Sub

Redis는 Pub/Sub 기능도 제공합니다.  
특정 채널에 메시지를 발행하면 해당 채널을 구독하는 클라이언트가 메시지를 받을 수 있는 방식입니다.  
이를 활용하면 실시간 알림, 채팅과 이벤트 전달 같은 기능을 구현할 수 있습니다.  

## 4. 데이터를 지키는 방법: 영속성·복제·고가용성 {#session-04}

Redis는 메모리를 기반으로 동작하지만, 안정적인 운영을 위해 데이터를 디스크에 저장하거나 여러 서버에 복제하는 기능도 제공합니다.  
이러한 기능을 사용하면 장애 상황에서도 데이터를 보호하고 서비스를 안정적으로 운영할 수 있습니다.  

![Redis 영속성, 복제, Sentinel과 Cluster 구성](/assets/images/nodejs/nodejs-redis/redis-persistence-ha.png)

> 영속성·복제·고가용성 구성은 데이터 유실 허용 범위와 서비스 규모에 따라 선택해야 합니다.  

### 🟦 RDB와 AOF 영속성

Redis의 대표적인 영속성 방식에는 RDB와 AOF가 있습니다.  

RDB는 특정 시점의 데이터를 스냅샷 형태로 저장하는 방식입니다.  
백업 파일을 만들기 쉽고 복구 속도가 빠르다는 장점이 있습니다.  
다만 저장 시점 이후에 장애가 발생하면 일부 데이터가 손실될 수 있습니다.  

AOF(Append Only File)는 Redis에서 실행된 쓰기 명령을 순서대로 기록하는 방식입니다.  
서버가 재시작될 때 기록된 명령을 다시 실행하여 데이터를 복구합니다.  
RDB보다 데이터 손실 가능성을 줄일 수 있지만 파일 크기가 커질 수 있고 복구 시간이 더 오래 걸릴 수 있습니다.  

### 🟦 복제

Redis는 복제 기능도 제공합니다.  
Primary 서버에 저장된 데이터를 Replica 서버로 복사할 수 있습니다.  
이를 통해 읽기 요청을 분산하거나 장애 발생 시 대체 서버를 활용할 수 있습니다.  

### 🟦 Sentinel

고가용성을 위해서는 Redis Sentinel을 사용할 수 있습니다.  
여러 Sentinel 프로세스가 Redis 서버 상태를 감시하고, 정족수 조건을 충족한 상태에서 Primary 서버에 문제가 있다고 판단하면 Replica 서버 중 하나를 새로운 Primary로 전환합니다.  
이를 통해 장애 상황에서 서비스 중단 시간을 줄일 수 있습니다.  

### 🟦 Redis Cluster

더 큰 규모의 서비스에서는 Redis Cluster를 사용할 수 있습니다.  
Redis Cluster는 데이터를 여러 서버에 나누어 저장하는 방식입니다.  
이를 통해 더 많은 데이터를 저장하고 더 많은 요청을 처리할 수 있습니다.
